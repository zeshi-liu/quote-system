# 回款台账与分次登记试用说明

本批沿用 PRD v3 已确认规则，基于历史档案分支继续开发。只在隔离虚构数据中验证，不表示实际收款、退款、微信或云端已验收。

## 账本规则

- 正常订单医院最终确认后已有唯一应收；全缺货不产生应收，零元应收显示已结清。
- 销售按订单登记实际金额、实际回款日期及备注。每次金额必须大于零且不超过当前未收余额；实际日期不晚于北京时间今天。实际日期与系统录入时间分别保存。
- 已收只合计有效回款；未收等于应收减有效已收。部分回款不重置账期，报价已完成仍可跟进回款。
- 误录由订单负责销售员填写原因作废，保留原金额、日期、署名、录入时间和作废依据，再关联新记录重录。作废仅纠正台账，不表示发生退款。
- 医院现负责人只读旧单；原订单负责人仍可登记和作废。管理员仅 PC 全量只读，无关销售、医院及厂家无台账权限。
- 钱款写入遵守同一根单与应收锁、锁后重新求和以及持久幂等。网络结果不明时先核对同一操作，不能换请求标识再记一笔。

## 本批及后续边界

本批提供正常单应收台账、分次登记、超额拦截、作废关联重录及历史档案余额联动。账期调整、医院默认账期维护、催收异常、每日提醒/微信订阅、历史纸单核实与金额更正、凭证上传仍为后续批次；不显示虚构的成功回执。

数据结构可保存未来历史累计类型，但本批不提供历史核实入口，也不能让普通登记请求自行指定历史累计类型。

## 启动与验证

API、数据库、PC 与小程序启动沿用[核心流程指南](mini-core-trial-guide.md)和[档案指南](order-archive-trial-guide.md)。PC 本机端口 5176，小程序 H5 联调端口由启动参数指定；PC 生产需同源 HTTPS 和显式允许来源。未注册小程序时继续本地工程验证，不发布真实微信体验版。

```sh
pnpm test:offline
pnpm test:ui
pnpm typecheck
pnpm build
```

标准 PostgreSQL 使用独立测试库运行 `pnpm test`。其中原生并发测试验证两端对同一余额同时登记及作废/新增的锁顺序；PGlite 下该用例跳过，不能拿离线串行通过替代原生并发。
