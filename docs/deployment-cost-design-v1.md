# 开发设计说明书第五部分腾讯云部署与成本

- 日期：2026-10-16
- 状态：A 单机自建试用路线及本部分整体方案已于 2026-10-16 确认；预算、地域、具体采购配置和云资源采购未确认。
- 已知规模：首批实际 2 名销售员；用户要求先比较成本再定预算。
- 基线：[PRD v3](quote-system-prd-v3.md) 及已确认的前四部分设计，时间规则见 [第四部分](state-time-boundary-design-v1.md)。

两名销售员试用已选择 A：一台腾讯云服务器自建 PostgreSQL，附件和异机备份存入 COS；B 托管数据库保留为后续迁移备选。医院和厂家仍有独立访问入口，实际订单量、附件规模及外部并发要在压测和试运行中核对。本部分已确认设计目标和试用初值，尚未购买、部署或完成恢复演练。

## 一 两种部署组合

| 项目 | A 自建数据库试用 | B 托管数据库 |
| --- | --- | --- |
| 应用 | 一台 Linux CVM，运行 HTTPS 入口、PC/H5 静态文件、NestJS API、独立 worker | 一台 Linux CVM，运行相同应用。 |
| 数据库 | 同机 PostgreSQL，独立持久化数据目录，不放在容器临时层 | TencentDB for PostgreSQL，通过同地域同 VPC 内网连接。 |
| 初始评估规格 | 2 核 4 GiB；磁盘依据实际可用空间配置，公开价格参考为 50 GB 系统盘 | 应用 2 核 4 GiB；数据库比较 1 核 2 GiB 与 2 核 4 GiB，20～50 GB 存储，按实际地域售卖规格核价。 |
| 任务 | PDF/Excel 生成和文件解析先限制重任务并发为 1，队列持久化到 PostgreSQL | 同样限制重任务并发，避免小实例被批量导出占满。 |
| 文件 | COS 私有业务桶，备份另设私有桶及独立权限 | 相同。 |
| 主要取舍 | 云资源支出较少；数据库升级、备份、恢复和同机资源竞争由项目运维负责 | 增加数据库费用，使用云数据库的高可用、备份和恢复能力，仍须做应用恢复演练。 |

规格是压测起点，不是性能保证。若两名销售加医院/厂家访问时仍出现持续资源紧张、解析或导出排队影响业务，先评估升为 4 核 8 GiB 或拆出 worker，再依据数据决定。报价、回款和权限口径均不因部署组合改变。

腾讯云公开规格包含 PostgreSQL 高可用主实例及上述小规格；正式选购须核对地域、存储介质和实际配置，不把只读实例当成可独立记账的数据库。[PostgreSQL 实例类型与规格](https://cloud.tencent.com/document/product/409/7562)。

试用按已选 A 继续设计；上线前须明确承担数据库维护和恢复的人员。若维护责任无法落实，或实测不能满足恢复目标，再提出 B 的配置报价供决策。正式用于持续回款台账前须完成备份恢复和真实权限验收。

## 二 部署和网络

- PC 与 H5 使用同一 HTTPS 入口下的不同页面路径，API 经同源 `/api/v1` 反向代理。厂家 H5 仍使用任务级凭证，不因同域获得内部 Cookie 权限。
- API、worker 和数据库为独立进程或容器；进程停止、健康检查、日志和资源限制分别配置。小规模沿用 PostgreSQL 持久化任务，不另建 Redis 或消息队列集群。
- 公网只开放 HTTPS；HTTP 仅用于重定向和必要证书验证。数据库不开放公网端口，API 运行端口不直接暴露；运维登录限制来源。运行数据库账号与迁移账号分离。
- B 中应用与数据库放同地域、同 VPC，通过内网访问；选择地域时先核对医院所在地及已有资源，不把价格参考中的北京自动当成最终地域。[腾讯云 PostgreSQL 连接说明](https://cloud.tencent.com/document/product/409/40429)。
- 试用与正式数据分开：开发使用本地合成数据，云端试用使用独立配置与桶。若另外开云端测试实例，其费用单列，不能假定已包含在一台服务器中。
- 域名、证书和真实小程序主体/类目/域名配置需逐项核对。使用中国大陆服务器对外提供网站服务前，应完成相应备案；服务器价格并不包含域名、微信主体或业务能力开通。[腾讯云备案指引](https://cloud.tencent.com/document/product/243/39038)。

### 2.1 单机资源和任务配置

构建在开发或构建环境完成，服务器运行已构建产物，不在有业务写入时执行依赖安装和前端构建。PostgreSQL 数据目录独立持久化并记录挂载位置；重建应用、容器或重启不能删除该目录。开发阶段锁定受支持的稳定版本与镜像摘要，数据库大版本升级另做备份和恢复演练。

- PDF/Excel 生成和采购文件解析共用重任务并发上限 1；提醒使用独立的轻量派发通道，避免长导出阻塞 09:00 任务。数据库备份另设单任务锁，不重叠启动多份备份，并监测其与业务任务的资源竞争。
- API 与 worker 的数据库连接池初始各最多 5 个连接，给备份和运维连接预留空间。压测后调整；业务不长期持有事务等待文件或外部响应。
- 重任务子进程初始内存上限 1 GiB，限制临时目录大小和日志增长；超限结束本次任务并按租约规则回收，不循环拉起同一失败文件。该上限须用真实 PDF/Excel 验证，不能把服务器全部内存分给 worker。
- 磁盘使用率达到 75% 告警、达到 85% 暂停接收新的文件重任务并提示维护；继续保留查询、低开销回款和到期列表入口。数据库实际写入失败时整笔回滚，不能显示登记成功。清理仅针对已轮转日志、过期快照和符合条件的临时对象，不能删除订单或回款腾空间。

以下为已确认的可配置试用初值，实现阶段须做故障验证；不改变已确认的厂家 48 小时链接、价格有效期和每日提醒口径。

| 参数 | 初值及处理 |
| --- | --- |
| 图表查询快照 | 从生成时起有效 10 分钟，到期返回刷新提示，图表与下钻一并重算；权限范围变化立即失效。每小时清理过期快照。 |
| 后台执行租约 | 120 秒，每 30 秒续租；超过租约即丧失提交资格，重新领取须增加执行代次。旧进程迟到仍不能提交。 |
| 首次导出占用 | 准备事务提交起最多 10 分钟，包含排队和重试；执行续租不能延长该截止。到期按根锁及代次回收，页面可重新发起导出，不自动改动已完成或作废状态。 |
| 单次重任务 | 实际执行最多 5 分钟；超时终止子进程并处理租约。外部请求单独设更短超时，不能靠定时器中止网络就推断对方未处理。 |
| 自动重试 | 可安全重试的临时故障最多 3 次执行，间隔 30 秒、120 秒，加入少量随机延迟；不突破导出总截止。参数/权限/业务状态错误不自动重试；通知结果未知仍按 outcome_unknown 处理，不自动重发。 |
| 临时对象清理 | 临时文件创建满 24 小时且无任何成功业务引用、无有效执行占用时才可删除；每日巡检。业务原文件、已冻结导出及审计不套用此期限。 |

若生成和备份超时或内存不足，应根据测量调整参数、扩容或拆分进程；不得以放宽金额、权限、状态校验来换取吞吐量。

## 三 成本对比

### 3.1 公开参考与估算边界

2026-10-16 核对到腾讯云 CVM 产品页展示：北京标准型 SA5、2 核 4 GB、50 GB 系统盘、1 Mbps，**1567 元/年**，按 12 个月摊销为 **130.58 元/月**。这是页面上的配置参考，不能视为本账号的采购价、按月购买价或续费承诺；购买前须重查地域、配置、折扣和续费价。[CVM 公开展示配置](https://cloud.tencent.com/product/cvm)。

另暂预留文件、异机备份及少量运维日志合计 **20～60 元/月**，这是本方案的预算假设，不是 COS 的固定套餐或测得账单。附件数量、保留版本、备份体积、请求和下载流量会改变支出。

### 3.4 OCR 与流量

OCR 单独比较实际所需的图片/PDF 识别能力、计费单位、资源包和超额价，不把其他 OCR 接口的免费额度当作已获得。Excel 直接解析及人工录入继续可用；识别失败不能自动确认采购明细。

上传/下载尽量通过有权限的 COS 临时授权处理；小程序实际可用域名、HTTPS、文件上传下载及微信内打开 H5 均须真机验证。流量、请求和附件长期增长按实际账单复核，不以两名销售推定永久固定费用。

## 四 备份和恢复建议

### 4.1 A 的试用方案

- 每小时使用匹配数据库版本的 `pg_dump` 生成一致性逻辑备份，建议 custom 格式，成功后上传独立私有备份桶并核对大小、校验和和归档目录可读性；记录备份开始时的数据时间、结束时间和对象标识。同机副本不算异机备份，归档可读也不等于恢复成功。[PostgreSQL pg_dump 说明](https://www.postgresql.org/docs/current/app-pgdump.html)。
- 角色、权限、扩展和部署配置另保留可重建清单，凭证在安全配置中管理；单库逻辑备份不包含整个实例的全部全局对象。初始方案不提供任意时间点恢复，最多恢复到经验证的备份点。
- 初始保留最近 24 个小时备份和 7 个每日备份，去重选取日备，不因备份保留周期删除业务订单及原始文件。备份体积和保留量纳入实际成本。
- 暂以恢复点不超过 2 小时、恢复服务不超过 4 小时作为试用目标。定时频率不等于目标已经达成，须计算成功备份的实际数据时间并演练；有连续失败时不能继续宣称该恢复点可用。
- 备份失败立即告警，最近成功上传的备份数据时间距今超过 90 分钟再次告警，达到 2 小时视为恢复点目标失守并人工处理。告警不依赖业务 API 正常运行，须从外部监测备份新鲜度和服务器存活。
- 开始使用真实订单前完成一次隔离恢复，之后每月至少演练一次，并在数据库大版本或备份方式变更后追加演练。数据库运维、备份失败告警、补丁和恢复演练须有明确维护责任；责任人及告警接收方式在开通资源前落实。上述恢复目标已获设计确认，是否实际达标须取得演练证据。

### 4.2 B 的方案

选购时核对自动数据备份、日志备份、时间点恢复能力、可恢复窗口及费用；拟从 7 天恢复窗口评估，另保留发布前备份。恢复目标需在实际规格上验证，不能把高可用切换、备份文件存在或供应商可用性说明当作本系统已经恢复成功。[腾讯云备份管理](https://cloud.tencent.com/document/product/409/131309)。

### 4.3 文件和数据库共同恢复

- 业务文件采用不可覆盖对象键，并保留对象标识、版本（如启用）、大小及校验和；数据库中引用的原采购资料和冻结报价文件须能找到对应对象。
- COS 版本控制可保留历史版本；建议开启业务桶版本控制，备份桶权限与业务上传账号分离。版本控制不能替代独立备份和权限隔离，生命周期不删除仍被业务引用的资料。[COS 数据安全说明](https://cloud.tencent.com/document/product/436/30738)。
- 恢复前进入维护模式，停止旧 API 写入和 worker 派发，选定数据库恢复点，核对对应对象及金额、确认版本、有效回款和任务状态。
- 恢复后撤销旧用户/H5 会话及受限票据，使恢复出来的旧填写链接不能重新生效；重新开通任务按业务规则操作，不直接恢复旧 token。凭证失效不自动替代厂家原始提交或改写报价金额。
- 备份点之后实际发生的回款、发送和医院确认须与线下依据核对；外部调用结果不确定的任务不盲目重发。确认余额与文件关联、当前权限及通知去重后再恢复服务，只评估当天催收。

## 五 发布与迁移

发布记录代码提交、构建产物、数据库迁移版本和配置版本；密钥、数据库密码、微信 AppSecret、COS 凭证不进入仓库或镜像。单机试用采用短时维护窗口，提前在页面告知，不承诺无停机发布。

1. 在隔离环境检查构建、迁移和关键业务场景；先准备新旧产物及兼容性说明，不在生产首次试迁移。
2. 进入维护模式，停止新业务写入和任务领取；等待正在执行的短事务结束，任务按代次安全结束或明确取消，不强行把未知通知记成未发送。
3. 生成并验证发布前异机备份，保存当前配置和迁移版本；失败则停止发布。由专用迁移账号执行迁移，禁止应用启动时多进程同时自动迁移。
4. 启动新 API，先检查数据库连接、迁移版本、私有文件权限和关键只读页面。通过后恢复写入及 worker，核对积压任务、真实订单写入和当天提醒资格。
5. 兼容迁移下可回滚应用产物；不自动回滚数据库或撤销已经发生的回款。若需恢复数据库，按第四节维护、凭证撤销及备份点后核对流程处理；不能直接覆盖新写入。

若 A 迁移至 B：先在隔离环境演练，核对主键、金额、最终确认、回款和文件引用；正式切换时停止写入与 worker，备份并恢复至目标，核对后切换连接。不能让两个数据库同时接收业务写入；切换后已有新写入时，不直接改回旧库而丢失新增记录。
