# 需求共识记录（2026-07-05）

本文件记录 2026-07-05 重新梳理后的产品共识。后续 PRD、原型和开发计划应优先遵循本文件，旧版 Web 内部报价系统假设不再作为 MVP 基准。

## 1. 产品形态

- MVP 不做 Web 端。
- MVP 采用「一个微信小程序 + 厂家外部 H5 报价链接」。
- 微信小程序承载销售员端和医院采购员轻量端。
- 厂家报价员不进入小程序，不注册、不登录、不授权；销售员通过微信发送 H5 报价链接，厂家报价员点开填写本次采购单报价表单。

## 2. 报价核心原则

- 报价主流程采用「本次厂家报价」。
- 去掉旧逻辑：系统不再自动使用当前有效厂家报价库匹配每个采购品类的厂家最新报价。
- 报价价格只来自：
  - 厂家针对本次采购单提交的本次报价。
  - 销售员在报价工作台的二次改价。
- 商品库价格、低频厂家全品类报价不得自动进入报价工作台价格计算。

## 3. 商品库定位

- 商品库是独立主数据模块。
- 低频厂家全品类报价可用于沉淀商品资料。
- 商品库用于商品查询、医院端选品、采购单品名标准化、别名匹配。
- 商品库包含标准品名、别名、规格、单位、分类、状态等信息。
- 商品库没有的品类，医院端允许自定义输入；销售员校对时可标准化或保留为本次自定义项。

## 4. 医院采购员端

- 医院端是微信小程序轻量端。
- 医院采购员使用微信手机号登录。
- 手机号必须由销售员或内部人员提前维护并绑定医院。
- 医院端 MVP 只做：
  - 提交采购单。
  - 查看自己提交的采购单状态。
- 医院端 MVP 不做：
  - 查看报价单。
  - 在线确认报价。
  - 在线反馈价格问题。

## 5. 医院采购单提交方式

医院端支持三种采购单提交方式：

- 上传图片：手写或纸质采购单拍照上传，系统 OCR 解析。
- 上传 Excel：系统自动解析采购明细。
- 商品库选品：从商品库搜索/点选品类，填写规格、数量、单位。

所有方式最终都转为结构化采购明细，并进入销售员端待校对流程。

## 6. 销售员端主流程

1. 医院采购员提交采购单。
2. 销售员收到采购单并校对品名、规格、数量、单位。
3. 销售员确认采购单后，为两个厂家生成本次 H5 报价链接。
4. 销售员通过微信发送报价链接给厂家报价员。
5. 厂家报价员填写本次采购单全部行价格并提交。
6. 至少一个厂家提交完整报价后，销售员可进入报价工作台。
7. 报价工作台展示本次厂家 A/B 报价、本次最低价、医院历史报价、销售员本次报价、加价率和风险提示。
8. 销售员完成二次改价后生成报价单。
9. 销售员导出 Excel/PDF/图片，并通过微信线下发给医院采购员。
10. 医院线下确认后，销售员标记完成；如反馈价格问题，销售员创建新版本报价单。

## 7. 厂家 H5 报价链接规则

- 链接只对应某一张采购单和某一个厂家报价任务。
- 页面只有一个报价表单。
- 表单行来自销售员已校对采购单明细。
- 厂家必须填写所有采购行价格后才能提交。
- 不支持部分提交。
- 不支持新增品类。
- 不支持替代品推荐。
- 不支持厂家自行修改已提交结果。
- 链接带 token 和有效期。
- 销售员端支持重新生成链接。
- 重新生成链接后旧链接立即失效。
- 同一厂家同一采购单同时只能有一个有效链接。

## 8. 关键状态

采购单状态建议：

- 草稿
- 已提交
- 校对中
- 待询价
- 厂家报价中
- 可改价
- 报价草稿
- 已导出报价
- 已完成

厂家报价任务状态建议：

- 未生成链接
- 待报价
- 已报价
- 已失效

## 9. MVP 明确不做

- 不做 Web 管理端。
- 不做厂家小程序端。
- 不做厂家账号体系。
- 不做医院端报价确认/反馈。
- 不做医院端查看报价单。
- 不做商品库价格自动报价。
- 不做低频厂家全品类报价自动进入主报价流程。
- 不做自动发货通知。
- 不做复杂审批流。
