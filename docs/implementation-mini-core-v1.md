## 目标与边界

本批建立 uni-app/Vue 3/TypeScript 小程序、Vue 3 厂家 H5、NestJS API 与 PostgreSQL，打通销售手工录入校对、冻结采购、两家厂家填写、紧凑表格比价及草稿计价保存。刷新、服务重启后仍能读取同一份业务数据。核心规则由服务端执行，浏览器原型不作为数据源。

不在本批承诺 OCR、COS 上传、文件导出、医院确认、应收/回款、分析、完整管理端或生产上线。它们仍属于 PRD 首版范围，后续批次实现；界面不放可点击但不工作的业务入口。微信身份适配与内部账号共用用户；AppID/AppSecret 通过环境配置，缺少真实配置时真机微信登录明确不可用，不生成假 OpenID。

## 执行任务

- [x] 1. 建立独立工作区及锁定依赖。依据 uni-app 官方 vite-ts 模板选兼容版本；Node 采用当前可用 24。构建目标为 `mp-weixin` 与 H5，不将 H5 构建成功写成微信真机通过。
- [x] 2. 先写金额规则失败测试：`12.50 × 0.01 = 0.13`、三类加价、非法精度、0/负数及派生溢出；实现独立十进制计算模块。运行 `pnpm test`，确认失败原因是模块/行为缺失，再实现并转绿。
- [x] 3. 建关系型迁移和事务测试。订单/修订/采购行、用户/医院/采购员/厂家、任务/链接/提交/报价行、报价草稿/行及审计分别保存；唯一约束限制两任务位且厂家不同。所有同单变更先锁根单，再核对负责人、修订与 expectedVersion，幂等结果和写入同事务提交。
- [x] 4. 实现真实账号与微信绑定适配。临时配置缺失返回明确错误；本地仅通过显式非生产密码入口联调；绑定测试向隔离测试库写入凭证验证一次性、冲突、过期、停用及撤销，不替代真实微信交换；生产路径不允许跳过身份验证。
- [x] 5. 写采购流程集成测试后实现创建/读取/校对/冻结。固定 kg、正数两位小数、医院及具体采购员同院、接收日非未来、冻结行只读；医院账期和负责人按创建时保存。未实现采购修订创建前不提供该入口。
- [x] 6. 写厂家任务与完整提交测试后实现。只存 token 哈希；48 小时精确到期；关闭页面后不可恢复原文；未提交重置和已提交重询分别校验。缺行、跨行、改规格/单位、0 价、重复提交与失效凭证均拒绝；报价有效至日独立校验。
- [x] 7. 写比价与计价测试后实现。0 家不能进入、1 家需明确提前确认；默认最低有效基准，后到价不自动采用；主动采用保留最终价且基准变化清确认；手工基准锁定。重询立即使所选旧基准无效，最终值仍保留。双家缺货保留行，一缺一待不当缺货；推荐和最终价分开，低于基准必填原因。
- [x] 8. 实现手机表格与单行编辑，采购数量/规格放药品下，厂家价格列保持对齐，待提交/过期/缺货明确区分。保存前可撤销本地最近批量加价；版本冲突不覆盖，网络未知结果按账号持久化同幂等键及原请求并先查结果；not_found 不代表最终未提交，继续同键重试，不换新键。
- [x] 9. 实现真实厂家 H5。只显示当前任务采购字段、当前填写状态及报价期限；不泄露医院联系人、另一厂家、基准/加价及最终价。提交后只读、完整复核、失效与重试有明确反馈。
- [x] 10. 运行标准 PostgreSQL、API 全流程及两前端构建。浏览器检查单独记载；微信工具导入、真实 AppID 登录、手机触摸/键盘/长表和服务器 HTTPS 仍为未完成的外部验收项。

## 验收输入与关键断言

测试使用独立虚构医院/销售/厂家。创建 5 行采购，其中一行数量 `12.50`；A 完整报价后提前进入，B 后到更低价不得改变已采用基准；明确主动采用才更新，最终价格保留且需重新确认。A 缺货而 B 未提交时保持待结论，B 也明确缺货后才显示缺货，数量不删除。重置后旧凭证立即无效；重新询价不能通过幂等回执恢复原 token。并发提交/保存用相同根锁校验，不生成两份当前提交或覆盖新版本。重启服务后读取原订单、厂家原价和草稿结果一致。
