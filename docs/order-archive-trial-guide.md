# 历史订单档案试用说明

2026-10-23，沿用 PRD v3 与已确认的历史订单原型。本批基于报价交付分支开发，尚未替代真实微信、COS 或云端验收。

## 本批范围

销售 PC 与小程序使用同一档案查询：按医院、实际接收日期、单号/报价号/历次采购药品、业务状态、订单归属和已有应收筛选，可分页查全部订单。档案保留旧采购修订、厂家历次提交、报价各版本及文件、发送、实际确认和审计记录；当前草稿不会覆盖历史冻结快照。

医院交接后，旧订单仍由原订单负责人操作；新医院负责人可只读查看。无关销售不能读取列表总数、医院选项、详情或下载。管理员仅通过 PC 身份只读查看全量业务，本批未增加账号维护或完整 PC 业务编辑界面。

PC 使用管理员预建的内部账号密码，最长登录 7 天、闲置 8 小时失效；与小程序绑定同一内部身份。沿用已确认的受保护 Cookie 与 CSRF 方案，浏览器脚本及本地存储不保存 PC 会话凭证；仅非生产 HTTP 联调用独立开发 Cookie。PC 登录不依赖开发试用开关。医院账号不能进入内部档案，管理员也不能借此使用销售写接口。

安全迁移会一次性撤销原有会话，已有用户需重新登录；不删除微信绑定或业务资料。之后账号角色、启停或密码发生变化时，先前签发的会话失效，改回原状态也不恢复旧会话。

计价中的同院历史参考按订单去重：先取已确认版本，否则取最近已发送且未作废版本，再匹配当前品名/规格/kg，最多展示三张订单。当前手工录入尚无商品库 ID，因此明确标注文本匹配参考；同代表版的重复商品行分别保留，缺货不显示为零价，不自动填入当前计价字段。

## 真实数据边界

- 当前正常单来源为手工代录，尚无原单上传/OCR；原始附件为空时明确显示暂无附件。
- 回款登记尚未实施，档案只展示已有应收和“暂无回款登记记录”。零元应收与全缺货无应收分别展示，不把尚未登记当作线下已核对。
- 新操作保存当时署名；早期日志没有姓名快照时只能展示当前档案姓名并标识，不能补造当时署名。
- 历史纸单补录、分次回款/更正、提醒和五类分析图表继续保留在后续需求中，本批不提供虚假入口或示例记账。

## 本机启动与检查

数据库、API、厂家 H5 及小程序启动沿用 [核心流程指南](mini-core-trial-guide.md)。报价文件另见 [交付指南](quote-delivery-trial-guide.md)，API 与 worker 必须共享数据库和存储配置。

PC 启动命令与最终验证记录在本批验收后补齐。开发端口只用于本机联调；真实微信需要 AppID、合法 HTTPS 域名及真机验证。

## 验收清单

- 使用销售 A 查询，确认超过 100 单的分页、首尾日期、含 `%`/`_` 的字面搜索及历史修订药名均可定位。
- 将医院转交 B 后，A 能查旧单，B 可只读，C 无权；管理员 PC 可读，修改报价请求仍被拒绝。
- 在同单 V1/V2/V3、全缺货、零元应收以及未发送导出场景核对列表和最近三单参考。
- 详情返回原筛选列表；快速切换、查询失败、权限变化及会话失效不残留另一订单或旧权限数据。
- 本地离线检查、浏览器联调、标准 PostgreSQL CI、真实微信、COS/云端分别记录结果。

## 当前验证记录

后端已通过主任务完整本地 PGlite 回归 69/69，并通过独立需求复审及质量复审；PC 与小程序档案界面仍在实施，标准 PostgreSQL CI 尚待本批同步后核验。

独立审查修复了 PC Cookie/CSRF、角色变化旧会话提权，以及权限检查等待跨午夜时查询仍取旧日三项问题；相应回归均先失败后通过。档案与 PC 身份两组独立复跑共 29/29。现有 API、小程序及厂家 H5 类型检查通过。

隔离 HTTP 夹具已核对管理员 Cookie 登录、全量只读查询及退出，脚本响应不含会话 token；含价格应收 375.00、全缺货无应收及零金额应收 0.00 分别保留。三单历史参考显示 30.00、缺货和 0.01，当前计价最终价仍为空。这些使用虚构数据、PGlite 和内存对象存储，不代表真实 TLS、COS 或微信通过。
