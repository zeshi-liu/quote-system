# 中药饮片报价系统中保真原型说明 v2.1

> 本文与现有原型保留 2026-07-16 的原始 v2.1 范围。当前需求见 [PRD v3](quote-system-prd-v3.md)，新增销售 PC、历史订单档案、回款及数据分析尚未反映在本原型中，本文不能作为新增功能的验收依据。

- 版本：v2.1
- 日期：2026-07-16
- 对应需求：2026-07-16 的原始 PRD v2.1；最新需求文档为 `docs/quote-system-prd-v3.md`。
- 原型入口：`prototype/index.html`

## 1. 原型目标

本原型用于验证 MVP 的三端协作：

1. 销售员在微信小程序中处理采购单、本次厂家询价、计价和医院报价版本。
2. 医院采购员在同一微信小程序的轻量角色端提交采购单并查看状态。
3. 厂家报价员不进入小程序，通过销售员发送的 H5 链接填写本次采购报价。

原型不连接后端，不执行真实 OCR、Excel 解析、微信授权、文件导出或消息发送。上述能力均使用本地状态模拟，但页面状态和交互约束必须与 PRD 一致。

## 2. 设计方向

### 2.1 产品形态

- 主界面按照 430px 微信小程序视口设计。
- 桌面浏览器仅显示原型场景切换栏和手机画布，不模拟 Web 管理端。
- 移动浏览器顶部保留紧凑的“销售员小程序 / 医院轻量端 / 厂家 H5”原型切换。
- 销售端和医院端使用底部导航，厂家 H5 不提供系统导航。

### 2.2 视觉原则

- 业务工具取向：高信息密度、清晰状态、低装饰。
- 主色使用药房绿，辅以黑、蓝、黄、红表示操作和风险，不使用大面积渐变。
- 页面区块不嵌套装饰卡片；卡片只用于任务、采购单、商品和计价行。
- 卡片和按钮圆角不超过 6px，状态标签可使用胶囊形。
- 所有固定导航层使用不透明背景，避免移动浏览器合成异常。

## 3. 原型数据基线

### 3.1 采购单

- 医院：市中医院。
- 采购单号：`CG-20260716-000108`。
- 来源：医院提交。
- 明细：党参、黄芪、炙甘草、陈皮，共 4 行。
- 数量和价格统一展示 2 位小数，单位默认 kg。

### 3.2 厂家任务

- 厂家 A：瑞康饮片有限公司，已完整提交。
- 厂家 B：本草源饮片有限公司，待报价。
- 厂家 A 的炙甘草为无法供货，其余行有报价。
- 厂家 B H5 提交后补齐全部行，使计价工作台获得完整有效基准价。

### 3.3 医院报价

- 报价单号：`BJ-20260716-HOSP01-001`。
- 初始版本：V1 草稿。
- 加价方式和参数初始均为空。
- 推荐价不会自动成为最终报价。
- 最终报价必须由销售员确认。

## 4. 信息架构

### 4.1 销售员小程序

底部导航：

| 导航 | 页面 |
| --- | --- |
| 工作台 | 高频待办、新建采购单、资料入口 |
| 采购单 | 采购单列表、状态筛选 |
| 报价单 | 当前报价和历史报价版本 |
| 商品库 | 标准商品、规格和来源历史 |

二级页面：

- 新建/校对采购单。
- 本次厂家询价。
- 计价工作台。
- 报价预览和版本操作。
- 商品详情。
- 厂家来源批次。

### 4.2 医院轻量端

底部导航：

- 首页。
- 采购单。
- 我的。

二级页面：

- 新建采购单。
- 采购单详情和状态时间线。

### 4.3 厂家 H5

- 本次采购报价表单。
- 提交成功页。
- 不显示其他采购单、另一厂家报价或系统菜单。

## 5. 销售员页面

### 5.1 工作台

首屏顺序：

1. 新建采购单主操作。
2. 待校对、厂家报价中、可计价三个状态计数。
3. 待处理任务列表。
4. 低频商品库和厂家来源批次入口。

强制规则：

- 厂家来源批次不能作为每日前置操作。
- 不出现“无厂家价可手工报价”的文案。
- 不出现厂家全品类报价参与本次计价的入口。

### 5.2 新建采购单

销售代录必须选择医院和采购员，并显示“销售代录”标签。

支持四种录入方式：

- 图片。
- Excel。
- 商品库。
- 自定义。

原型中点击对应操作模拟解析并生成采购明细。采购行至少包含名称、数量和单位，规格可为空。点击“确认并冻结”后进入本次厂家询价。

### 5.3 本次厂家询价

页面固定展示厂家 A/B 两个任务位：

- 厂家名称。
- 任务状态。
- 当前链接版本。
- 48 小时到期时间。
- 复制链接、打开 H5、重新生成/重新报价。

进入计价按钮规则：

| 完整提交数 | 按钮 |
| --- | --- |
| 0 家 | 禁用“等待厂家报价” |
| 1 家 | “提前进入计价”，需二次确认 |
| 2 家 | “进入计价” |

重新报价规则：

- 已提交厂家点击“重新报价”必须二次确认。
- 原提交立即退出本次计算，但保留历史。
- 使用原报价作为基准的草稿行立即失效。
- 已导出报价版本不受后续厂家重报影响。

### 5.4 计价工作台

移动端以逐行价格卡片呈现，不使用横向大表格。

每行必须同时展示：

- 品名、规格、数量和单位。
- 厂家 A/B 当前有效报价或供货状态。
- 本次最低价。
- 当前基准厂家和基准价。
- 同医院最近 3 次已发送历史价。
- 加价方式、参数、推荐价、最终报价和确认状态。

加价方式：

| 方式 | 公式 |
| --- | --- |
| 固定金额 | 基准价 + 固定金额 |
| 按比例 | 基准价 × (1 + 百分数 / 100) |
| 高开倍率 | 基准价 × 倍率 |
| 手工改价 | 销售员直接填写最终报价 |

批量加价规则：

- 加价方式和参数默认空。
- 批量操作只计算推荐价。
- “推荐价填入最终价”后仍需销售员确认。
- 无有效基准价的行自动跳过。
- 后到厂家报价不能覆盖已确认最终报价。

### 5.5 报价预览

预览模板字段：

- 医院名称。
- 报价单号。
- 版本号。
- 报价日期。
- 名称、规格、数量、单位、单价和金额。
- 含税提示和总金额。

导出阻断条件：

- 任一行无当前有效基准厂家价。
- 任一行最终报价为空或未确认。
- 最终报价低于基准价但未填写原因。
- 基准报价已被重新报价或厂家替换而失效。

版本规则：

- Excel 和 PDF 可使用同一版本分别导出。
- 首次成功导出后当前版本冻结。
- 导出不等于发送，必须单独点击“标记已发送”。
- 只有已发送版本可以登记医院确认。
- 已冻结版本不能返回计价编辑；修改必须创建下一版本。
- 厂家后续重报不改变已冻结版本的厂家报价快照。

### 5.6 商品库和来源批次

商品库支持按标准品名和别名搜索，并展示商品规格。

商品详情可查看厂家全品类来源历史，但必须固定展示：

> 以下价格仅资料参考，不参与本次报价。

来源批次支持 Excel 和手工录入的原型入口。每次创建独立系统批次号，厂家原始批次号允许重复；批次确认后不可编辑，只可查看或整体作废。

## 6. 医院端页面

### 6.1 首页和采购单列表

- 主操作为“提交采购单”。
- 每张采购单显示编号、日期、品类数量、状态和来源标签。
- 来源标签严格区分“医院提交”和“销售代录”。
- 医院端不展示厂家、价格、销售加价或报价文件。

### 6.2 新建采购单

支持图片、Excel、商品库和自定义四种方式。单位缺失时默认 kg，提交前可修改。

提交后：

- 生成新的采购单编号。
- 来源标签为“医院提交”。
- 状态进入“报价处理中”。
- 医院采购员不能继续编辑。

### 6.3 采购单详情

- 展示采购明细和简化状态时间线。
- 销售代录的采购单显示只读提示。
- 不提供报价查看、下载、线上确认和价格反馈。

## 7. 厂家 H5 页面

### 7.1 表单信息

- 厂家名称。
- 医院和采购单号。
- 截止时间。
- 链接版本。
- 固定“含税、含抽点”价格口径。

### 7.2 行级填写

每行必须选择：

- 可供货：单价必填且大于 0。
- 无法供货：单价清空，备注选填。

全部采购行完成后才能提交。表单不允许新增、删除或替代商品。

### 7.3 提交后

- 生成不可变的厂家提交版本。
- 原链接进入已提交状态。
- 页面只显示提交成功和本次提交摘要。
- 需要更正时必须联系销售员重新生成链接。

## 8. 原型验收路径

### 8.1 主路径

1. 销售工作台进入本次厂家询价。
2. 厂家 A 已报价，销售员二次确认后提前进入计价。
3. 切换到厂家 H5，厂家 B 填写示例报价并完整提交。
4. 返回销售端计价工作台。
5. 批量选择按比例 10%，计算推荐价。
6. 将推荐价填入最终价并确认全部。
7. 预览报价单并分别导出 Excel/PDF。
8. 标记已发送医院。
9. 登记医院确认版本。

### 8.2 异常路径

- 厂家 H5 未完成全部行时阻止提交。
- 仅一家报价时显示提前计价确认。
- 两家同一行均无法供货时阻止导出。
- 厂家重新报价后旧基准失效。
- 低于基准价时要求原因。
- 已导出版本阻止返回计价编辑。
- 已导出 V1 在厂家重报后仍可导出同版本另一格式。
- 医院端销售代录采购单只读。

## 9. 响应式验收

- 390 × 844：无横向溢出，顶部场景切换和底部导航可见。
- 430 × 900：价格卡片、固定操作栏和表单字段不重叠。
- 1200 × 900：左侧场景栏与手机画布并列，不扩展为 Web 后台。
- 所有长文本在按钮、标签、卡片和表单内可换行或截断，不覆盖相邻内容。

## 10. 开发边界

本原型仅演示原 v2.1 产品和交互，正式开发以当前 PRD v3 的数据对象、接口、状态机和测试标准为准，待确认细则需先收敛。不得直接把原型内存状态当作后端模型，也不得把场景切换栏实现到正式小程序中。
