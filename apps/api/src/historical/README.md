# 历史纸单补录后端实施与边界

依据 PRD v3 7.15、7.16、7.18、7.21 与已确认事务、身份和日期设计。

1. 先用隔离数据库测试完整性、权限、未知结果、幂等和金额更正下限。
2. 独立历史来源，根单仍保留修订，草稿允许未知，核实后封存真实采购明细。
3. 核实事务建立唯一历史应收及可选历史累计回款；全缺货无应收，未知结果零金额有零余额应收。
4. 金额更正先锁根单和已有应收，再锁历史资料并重算有效已收；保留首次核实与每次独立依据。
5. 档案加入历史投影，不伪造厂家、报价、导出或发送；医院端全部拒绝。

`HistoricalService(store, files?)` 提供 create/save/list/detail/verify/correctAmount/void。HTTP 挂接及全局普通采购入口来源保护由主任务集成。附件可空，有附件时必须通过 `SourceFileService.requireReference` 校验同单专用历史引用。PGlite 用于离线功能联调；多连接竞争用例仅在标准 PostgreSQL CI 执行。
